# Pinned C++ Surface pilot

The pilot is prepared for owner review. Scientific parity has **not** been
approved. Python remains the behavioral reference, and neither backend's science
has changed. The numeric policy is unapproved and cannot certify a comparison.

The reference revision is `firelab/behave`
`f3b2943e69abca942e795c5b1b45276f6338abb5`. Observations were generated by a
source-hashed external preparation build using MSVC 19.50.35728, C++14,
`/fp:precise`, and `/D_USE_MATH_DEFINES=`. No upstream implementation or notice
text is vendored into this repository.

## Observations and coverage

The stored Surface dataset contains 634 cases, including all 83 defined numbered
fuel records, a five-direction grid, fixed weather/canopy profiles, extinction
and curing boundaries, and 24 seeded interior cases. An append-only extension adds 48 supported wind-height, orientation, and WAF combinations, plus an A/B/unavailable/A state sequence. The original 582 rows remain byte-identical. The stored input bytes are
authoritative; the generator and seed describe reproducibility rather than
replacing those inputs.

The oracle provides five fields for 583 cases: spread, intensity, flame length,
heat per unit area, and length-to-width ratio. Fifty-one cases are unavailable under
F-013. No geometry or other invented value is attached to those rows. Rejection
controls separately cover invalid IDs and unsupported or unsafe inputs.

Every public C++ method has a route-bundle assignment in the hybrid inventory.
The 266 scientific candidates also retain per-function statuses. The 486
no-counterpart entries remain excluded, and containment remains deferred.
Neither structural validity nor the existence of observations implies approved
numeric coverage. The readiness check rejects this pending state.

## Findings at the review gate

| Finding | Measured or source-backed difference | Current disposition |
| --- | --- | --- |
| F-012 | MSVC needs the empty `_USE_MATH_DEFINES` definition for the unchanged source. | Registered build note. |
| F-013 | Skipped zero-load calculations leave the separate FireSize geometry uninitialized. | Registered unsafe route; driver returns unavailable before Surface construction. |
| F-014 | Twenty-three C++ records store dead moisture-of-extinction values 100 times the Python fractional convention. | Open; no science change. |
| F-015 | The ports previously discarded effective wind at baseline spread at or below `1e-7 ft/min`. | Owner approved matching C++ for positive spread; zero-denominator guards retained. |
| F-016 | The ports previously returned positive flame length below the C++ intensity cutoff of `1e-7 BTU/ft/s`. | Owner approved the same strict cutoff; the threshold itself retains the Byram equation. |
| F-017 | Polynomial evaluation order gives different tiny extinction residuals. | Open floating-point comparison policy. |

The two approved boundary changes have scalar, array, staged/fused grid, and
standalone core regressions. Their approval does not approve tolerances, resolve
the fuel-table moisture discrepancy, or establish full C++ parity. Original
observations in the findings register remain historical evidence from before
the boundary changes.

For example, `fm159-angle0` has C++ intensity 2649.566089568236 and Python/Rust
intensity 1047.4059417058265 Btu/ft/s. The corresponding heat and spread differences
are explained by the stored moisture-of-extinction convention. This is not
evidence for silently adopting either convention.

Large relative errors near zero must be read with their absolute values. For
`fm204-extinction-below`, intensity is approximately `5.83e-29` in C++ and
`5.25e-28` in Python. The reporting tool records separate worst-case identities
for absolute and relative differences. No tolerance is inferred from that ratio.

## Offline checks and numeric diagnostics

Use the configured interpreter and the contributor procedures:

```shell
python tools/cpp_reference.py --check
python tools/cpp_inventory.py --check
python tools/export_cpp_crate.py --check
python -m pytest --require-rust -W error
python tools/cpp_reference.py --compare development/cpp-pilot/measurements
```

The first three commands check integrity, not scientific parity. The comparer
records every Python/C++ and Rust/C++ field difference without accepting it.
`assert_matches_cpp` raises until an explicit field policy is approved. The
standalone crate verifies its own copied fixture hashes, evaluates real core
cells, records raw differences, and likewise refuses to certify an unapproved
policy. No Python, C++, or NumPy runtime is added to the Rust library.

Manifest verification is divided deliberately. Offline readers verify shipped
goldens, policy, inventory, findings, tools, and crate-local copies. Historical
build-input hashes are provenance; the absent C++ sources, overlay, and executable
are not opened by an offline reader. Live verification additionally requires the
exact pinned checkout, clean source state, and matching source/driver identities.

## Dependency and distribution boundaries

The registered optional submodule at `reference/behave_cpp` is pinned to the
revision above. Ordinary test and distribution jobs need not initialize it.
The live checker requires its exact source and overlay hashes, rejects modified
inputs, and has no external-checkout fallback.

The original observations disclose their attested external preparation build.
After explicit owner authorization, the registered checkout was rebuilt using
the same toolchain and reproduced all 634 result rows byte for byte. Its 62
rejection controls, 51 geometry exclusions, poison positive controls, and state
sequence passed. This is source-integrity and same-toolchain reproduction
evidence, not approval of the open scientific findings or numeric policy.
Live CI qualification and cross-compiler calibration remain unclaimed.

The public Surface route did not link when its EXRATE implementations were
omitted. They are compiled in the local reference build, with their mixed
notices retained. The notice audit found 33 files without per-file wording and
14 author-notice files. No licensing conclusion follows from those counts.

The reference checkout and overlay are explicitly excluded from the sdist,
wheels, and crate archive. Archive checks reject those paths. Reviewed numeric
observations and their provenance are allowed; upstream source, notice text,
and reference binaries are not distributed.

Before approving numerical comparisons, resolve the open findings, approve
per-field and reproducibility bounds from measurements, and approve the measured
fixture budget. Existing tolerances and scientific fixtures remain unchanged.
